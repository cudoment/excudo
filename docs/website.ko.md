# 웹 사이트

[README](../README.ko.md) | [English](website.md) | 한국어

## 메모를 웹 사이트로 보기

엔진은 메모를 cudoc-export로 웹 사이트로 쓸 수 있습니다. Tine이 없는 곳, 즉 컴퓨터의 브라우저,
휴대폰, 정적 호스팅에서 읽기 위해서입니다. 노드마다 한 페이지가 되고 페이지 끝에는 그 아래 노드의
접히는 트리가 붙습니다. 홈과 생성 뷰도 페이지가 되며, `{{query}}`는 사이트를 만들 때의 결과로
바뀝니다. 저널은 설정하면 들어갑니다. `[[페이지]]`는 링크가 되고, 할 일은 상태가 보이는 체크박스가
되며, `DEADLINE:`은 할 일 옆의 날짜가 되고, 아웃라이너 자신의 속성(`collapsed::`, `id::`)은
빠집니다. 웹 사이트는 줄마다 메모의 주소(`data-excudo-page`, `data-excudo-line`)를 지니므로, 도구가
페이지의 줄에서 파일로 되돌아갈 수 있습니다.

```js
site: {
  out: ".excudo/site",   // 작업 폴더 기준이나 ~/…. 그래프 밖이며 통째로 바꿔 씁니다
  title: "내 메모",       // 정하지 않으면 작업 폴더 이름
  mode: "site",          // "standalone"이면 홈 한 쪽에 모든 것을 담아 보낼 수 있습니다
  open: 0,               // 노드 트리를 처음에 펼쳐 두는 깊이. 정하지 않으면 접습니다
  journals: false,       // 저널을 저널 페이지 아래에 넣습니다
  css: [],               // 엔진의 스타일 다음에 읽을 스타일시트
  onSave: true,          // build와 save도 웹 사이트를 씁니다. false면 site만 씁니다
},
```

내보내기 도구는 한 번만 설치합니다(`CUDOC_SKIP_BROWSER_DOWNLOAD=1 npm install cudoc-export@^1.0.0`,
엔진은 웹 사이트를 쓸 때만 읽습니다). 그다음 `excudo site`를 실행하고, `--open`을 붙이면 홈을 엽니다.
페이지의 절(쿼리 결과, 노드 아래 트리)은 접힌 채 시작하므로 페이지를 제목부터 읽습니다. 페이지마다
작은 런타임이 노드를 검색하고 홈에 마지막으로 본 페이지를 보여 줍니다. 옆의 문서 목록은 넓은 화면에서
지금 페이지까지의 경로만 펼칩니다. 좁은 화면에서는 목록이 페이지에서 빠지고, 떠 있는 버튼이 목록을
페이지 위의 패널로 접힌 채 엽니다. 패널은 바깥을 누르거나 Esc를 누르거나 링크를 따라가면 닫힙니다.
목록의 버튼으로 모두 펼치거나 접을 수 있습니다. 연 상태는 기기마다 기억합니다. 런타임은 서버가 필요
없고, 페이지의 정책은 웹 사이트 자신의 받는 곳(아래 절)만 허용합니다.
`check`는 웹 사이트가 보여 줄 수 없는 쿼리를 알립니다(`query-unsupported`). 읽는 형태는 `and`, `or`,
`not`, `task`, `[[페이지]]`, `"글"`, `(page "이름")`입니다. 폴더를 어디로 보낼지는 사용자가 정하며,
다음 절처럼 엔진이 사용자의 로그인으로 지키는 곳에 올릴 수도 있습니다.

### 내 로그인으로만 여는 곳에 올리기

명령 하나로 웹 사이트를 Vercel에 올립니다. 사용자의 Vercel 로그인으로만 열리며, 휴대폰으로 열 코드도
보여 줍니다.

```sh
npx --no-install excudo site setup
```

없는 것(내보내기 도구, Vercel CLI)을 설치하고 웹 사이트를 씁니다. 그다음 브라우저에 Vercel의 기기
로그인을 열고, 사용자가 그곳에서 허용할 때까지 기다립니다. 프로젝트를 만들어 연결하고(폴더 이름에
`-memo`를 붙인 이름, 또는 `--project <이름>`), Vercel Authentication이 production 주소를 포함한 모든
배포를 지키게 한 뒤 올립니다. 끝으로 주소를 열고 복사하며 코드를 보여 줍니다. 무료 Vercel 계정으로
충분하며, Vercel의 Hobby 플랜은 개인 용도입니다. 다시 실행하면 이미 된 단계는 건너뜁니다.

그 뒤로는 `excudo site publish`가 웹 사이트를 쓰고 바뀐 것이 있을 때 올립니다. 보호 범위가 모든
배포보다 좁으면 올리지 않고, 사용자가 먼저 할 일이 있으면 75로 끝나므로 예약 실행이 불렀다가 나중에
다시 할 수 있습니다. `excudo site open`은 주소를 코드와 함께 다시 열고, `excudo site status`는 로그인,
프로젝트, 보호, 마지막 배포를 보여 줍니다. 로그인은 CLI가 스스로 지닙니다. 엔진은 인증 정보를
입력하거나 저장하지 않고, 배포에 마지막 커밋의 메시지와 작성자가 함께 가지 않도록 git을 가립니다.

호스트 조회는 60초, 배포와 setup의 패키지 설치는 10분 안에 끝냅니다.
`EXCUDO_HOST_TIMEOUT`은 조회 제한을, `EXCUDO_DEPLOY_TIMEOUT`은 배포 제한을 초 단위로 바꿉니다.
게시나 이슈 읽기, 닫기가 네트워크, 프록시 문제로 실패하면 75로 끝나며 다음 실행에서 다시 시도합니다.
연결 실패를 로그인 해제로 안내하지 않습니다.

웹 사이트가 같고 24시간 안에 모든 배포의 보호를 확인했으면 호스트를 호출하지 않습니다.
24시간이 지나거나 `--force`를 쓰면 배포 전에 보호와 받는 곳의 토큰을 다시 확인합니다.
Vercel에서 토큰을 바꾼 뒤 바로 배포하려면 `--force`를 씁니다.

`site status`는 저장된 주소, 마지막 배포와 받는 곳의 토큰 시각을 먼저 보여 준 뒤 실시간으로 조회합니다.
상태 조회는 호출마다 10초로 제한하고 연결 불가를 표시하며, JSON에는 `reachable: false`를 담습니다.
웹 사이트의 GitHub 요청은 8초로 제한하고, 페이지는 실패한 이슈 조회를 나중에 다시 시도합니다.

```js
site: {
  publish: {
    project: "my-memo",          // Vercel 프로젝트. 정하지 않으면 폴더 이름에 -memo를 붙입니다
    dir: ".excudo/publish",      // Vercel이 받는 폴더. 웹 사이트와 그 설정만 둡니다
    open: ["node", "tab.mjs"],   // 링크를 마지막 인자로, EXCUDO_LINK=login|site|dashboard와 함께 엽니다. 기본은 브라우저
    close: ["node", "tab.mjs", "close"], // open이 처음 출력한 줄로 로그인 페이지를 닫습니다
    copy: true,                  // 주소를 열 때 복사합니다
  },
},
```

### 웹 사이트에서 할 일의 상태 바꾸기

받는 곳을 설정하면 페이지의 할 일 상태가 버튼이 됩니다. 누르면 TODO, DOING, WAITING, DONE, CANCELED(하지
않기로 한 일) 가운데 하나를 고르고, 체크박스를 체크하면 DONE이 됩니다. 고른 상태는 바로 보이고, 메모에 반영될 때까지
표시를 단 채 기기에서 기다립니다. 0.5초 안에 웹 사이트 자신의 함수(`api/edit`, `site publish`가
페이지 옆에 둡니다)에 가고, 함수는 묶음마다 사용자의 비공개 GitHub 저장소에 이슈 하나를 만듭니다.
이슈에는 줄의 주소와 상태만 있고 할 일의 글은 없습니다(아래 홈 보드를 저장한 것만 이슈에 글이 남습니다).

페이지는 메모가 아직 받지 않은 변경도 함수에 묻습니다. 열 때, 다시 화면에 나올 때, 기다리는 변경이
있는 동안 30초마다 묻습니다. 그래서 휴대폰에서 고른 상태가 컴퓨터에서도 보이고, 메모가 받은 변경은
다음 웹 사이트가 그대로 보여 줄 때까지 체크 표시와 함께 보입니다. 기다리는 변경이 있으면 상태 줄에
'지금 반영' 버튼이 나옵니다. 누르면 요청 이슈를 남기고(`api/sync`), 그 이슈를 자주 확인하는 컴퓨터가
평소 간격을 기다리지 않고 바로 가져옵니다.

설정 한 줄을 더하고 설정 명령을 다시 실행하면 켜집니다. 명령은 멈춘 곳부터 이어 갑니다.

```js
site: {
  inbox: true,   // 저장소를 지정하려면 { github: { repo: "me/memo-inbox" } }, 직접 만든 예약 실행이
                 // site pull을 부르면 schedule: false
},
```

```sh
npx --no-install excudo site setup
```

설정 명령은 GitHub CLI(`gh`, macOS에서는 Homebrew로 설치)로 GitHub에 로그인합니다. 로그인 페이지를 열고
코드를 복사해 둡니다. 그다음 받는 곳의 비공개 저장소(`<계정>/<프로젝트>-inbox`)를 만들고 페이지 두 개를
엽니다.

값이 채워진 GitHub 페이지에서 Repository access로 그 저장소를 고르고, 토큰을 만들어 복사합니다.
Vercel 페이지에서 `EXCUDO_INBOX_TOKEN`을 Production으로 더하고 값에 토큰을 붙여 넣은 뒤 저장합니다. 설정
명령은 변수가 보일 때까지 기다렸다가(이름만 읽고 값은 읽지 않습니다) 사이트를 올립니다. macOS에서는
`site pull`을 1분마다 예약하고, 다른 곳에서는 예약 도구에 넣을 명령을 알려 줍니다. 나중에 토큰을 바꾸면
다음 배포가 알아채고 다시 올립니다.

`excudo site pull`이 변경을 가져옵니다. 받는 곳의 열린 이슈를 읽어 5분마다 가져오고, 페이지가 요청했거나
`--now`를 붙이면 바로 가져옵니다. 그 페이지에 남은 사용자의 편집은 먼저 따로 커밋합니다. 쓴 페이지를
커밋한 뒤에 이슈를 닫고(확인할 일로 남긴 변경이 있으면 not planned, 아니면 completed), 사이트를 다시
올립니다. 메모는 사용자의 컴퓨터만 쓰고 저장소의 파일은 아무도 쓰지 않으므로, 두 변경이 병합에서
부딪치지 않습니다.

자기 사이트의 이슈만 가져오므로 두 메모가 받는 곳 하나를 함께 써도 됩니다. git이 없으면 기다립니다.
커밋해야 이슈를 닫을 수 있기 때문입니다. 기다려야 하는 배포(로그인, 보호 설정)는 남겨 두었다가 5분마다,
요청하면 바로 다시 올립니다.

변경은 그 줄에 페이지가 보여 준 할 일이 페이지가 보여 준 상태로 남아 있을 때만 반영합니다. 줄이
옮겨졌으면 같은 글이 그 페이지의 한 줄에만 있을 때 그 줄을 찾습니다. 그 밖에는 추측하지 않고, 오늘
저널에 줄과 고른 상태를 적은 WAITING 할 일을 남깁니다. 변경마다 id로 기록하므로(`.excudo/received.json`)
같은 묶음을 두 번 읽어도 두 번 바꾸지 않습니다. 다음 웹 사이트가 메모에 반영된 변경을 페이지에
알리면, 페이지는 그 변경을 더 기다리지 않습니다. Vercel Authentication이 페이지처럼 함수도 지키며,
함수는 웹 사이트 자신의 페이지에서 온 요청만 받습니다.

직접 만든 예약 실행에서는 `site pull` 아래 단계인 `excudo receive --input <파일|->`를 쓸 수 있습니다. 묶음
하나, 묶음 목록, `gh issue list --json number,body`의 출력을 받습니다. 미리 보기(`--dry-run --json`)는 쓸
페이지를 `writes`에, 결과마다 그 변경이 쓴 파일을 `file`에 알려 주며, 이미 받은 변경도 마찬가지입니다.

### 홈의 대시보드

`dashboard`는 웹 사이트 홈 맨 위, 사용자의 홈 위에 대시보드를 둡니다. 원하는 구성을 원하는 순서로
적습니다. 구성마다 접는 상자이며 `open: false`가 아니면 펼쳐져 있고, 제목 줄에 숫자가 보이며,
접고 편 상태는 기기가 기억합니다. 이 설정이 없으면 홈은 전과 같습니다.

```js
site: {
  dashboard: {
    sections: [
      { type: "links", title: "업무", items: [{ title: "Jira", url: "https://…", icon: "J" }] },
      { type: "notes", page: "메모장" }, // 그 노드의 본문을 보며 고치는 보드. 받는 곳이 있어야 함
      { type: "tasks", except: ["보관"] }, // 상태별 열린 할 일, 지난 목표일, 할 일이 많은 노드(nodes: 8).
                                     // except의 노드와 그 아래 노드의 할 일은 세지 않음
      { type: "done", weeks: 8 },      // 주마다 끝낸 할 일
      { type: "agents", days: 14 },    // 날짜별 에이전트 세션, 비용, 맡긴 일
      { type: "runs", days: 7 },       // 예약 실행 단계별 마지막 결과, 실패한 것 먼저
    ],
  },
},
```

`group`은 여러 구성을 접는 상자 하나에 담고, 상자 안에서 구성마다 제목을 붙여 보여 줍니다:
`{ type: "group", title: "링크", sections: [{ type: "links", title: "업무", items: […] }, …] }`. 안의
구성은 묶음과 함께 접히므로 `open`을 받지 않고, 메모장과 다른 묶음은 넣지 않습니다. 묶음의 제목 줄은
링크만 담은 묶음이면 링크 수를 더해 보여 주고, 그 밖에는 구성마다 첫 숫자를 보여 줍니다.

링크는 새 탭에서 열리고 페이지에 관한 정보를 보내지 않습니다. `icon`은 한두 글자이며, 없으면
제목의 첫 글자를 씁니다. 페이지가 다른 사이트의 그림을 불러오지 않기 때문입니다. 숫자는 웹
사이트를 쓸 때 계산하며, 대시보드가 기준 시각을 함께 보여 줍니다. 끝낸 할 일은 열린 줄을 `DONE`으로
바꾼 커밋의 주에 셉니다. 끝낸 할 일을 다른 페이지로 옮긴 것은 다시 세지 않으며, 커밋마다 센 결과는
`.excudo/dashboard-done.json`에 남습니다.

메모장은 보드입니다. `page`가 가리키는 노드의 본문(제목과 요약 아래, 생성된 하위 문서 위)을 그
자리에서 보고 고치며, 한 줄이 한 항목이고 Tab과 Shift+Tab으로 줄을 들이거나 냅니다. 저장하면 본문
전체를 할 일 상태와 같은 길로 받는 곳에 보내고, 고치기 시작한 본문의 다이제스트를 함께 보내므로
그 이슈에는 사용자가 쓴 글이 남습니다. 빈 줄은 빠지고 목록 항목이 아닌 줄은 항목이 됩니다. 메모가
받기 전까지는 모든 기기에 저장한 보드가 대기 표시와 함께 보입니다. 저장하지 않은 수정은 기기에
남고, 수정 취소는 저장한 보드로 되돌립니다.

`site pull`은 노드가 고치기 시작한 본문 그대로이면 저장한 본문으로 바꿉니다. 그사이 Tine이나 다른
기기에서 바뀌었으면 줄 단위로 합칩니다. 서로 다른 줄의 수정은 모두 남고, 같은 자리에 더한 줄도
모두 남습니다. 같은 줄을 서로 다르게 고쳤으면 노드 쪽을 두고, 웹에서 쓴 줄은 보드 맨 아래의
