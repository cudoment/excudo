# 스킬

[README](../README.ko.md) | [English](skills.md) | 한국어

## 스킬은 코드를 품습니다

여기서 말하는 스킬은 프롬프트를 줄여 둔 것이 아니라, 작업의 일부를 매번 같은 방식으로 수행하는
코드를 품은 것입니다. 스킬 폴더에는 `SKILL.md`와 `scripts/`가 있고, 적어도 `scripts/check.*`와
`scripts/check.cases.json`이 있어야 합니다. 검사는 스킬의 요구 사항을 충족했는지 알리고(종료 코드
0 또는 1, 자세한 내용은 `--json`), 경우 파일에는 통과해야 하는 경우와 실패해야 하는 경우가 있습니다.
`skills lint`가 경우마다 facts를 검사에 직접 넘기고(`--facts <파일>`) 종료 코드를 보므로, 실패할 수
없는 검사는 걸러집니다.

경우는 동시에 실행하며, `EXCUDO_CASE_JOBS`로 동시 실행 수를 정합니다(1이면 순차 실행).
기본값은 CPU 병렬 처리 수에 따라 최대 8이며, 기대와 다른 결과는 혼자 재검사하고 도우미가 실패하면 모두 순차 실행합니다.

매번 같은 결과가 나와야 하는 검색과 변경은 `SKILL.md`가 실행하는 다른
스크립트에 둡니다. 스킬은 필수 검사를 모두 통과해야 하고, 품질 기준으로 0점부터 100점까지 점수를 받습니다.

| 기준 | 점수 | 확인하는 것 |
| --- | --- | --- |
| 필수 | - | 폴더 이름과 설명이 있는 `SKILL.md`, 스크립트, `scripts/check.*`, 경우를 예상대로 판정함(통과해야 하는 경우와 실패해야 하는 경우가 하나 이상씩), `SKILL.md`가 모든 스크립트를 실행하고 가리킨 스크립트가 모두 있음, 스크립트 문법, 남은 `FILL IN:` 표시 없음, 특정 에이전트만 아는 도구 호출 없음, 비밀 값 없음, 학습 스킬이면 요청 문구를 옮겨 적지 않고 사용자가 지적한 실수로 기록한 경우가 모두 실패해야 하는 경우로 남아 있음 |
| `runs-check` | 25 | `SKILL.md`가 명령 블록에서 검사를 실행함 |
| `triggers` | 20 | 설명이 스킬을 언제 쓰는지 밝힘 |
| `usage` | 20 | 스크립트마다 맨 위에 사용법이 있음 |
| `portable` | 20 | 이 컴퓨터의 홈 폴더 경로가 없음 |
| `size` | 15 | `SKILL.md`가 500줄 이하이며 따라 할 만큼의 내용이 있음 |

작업을 저장했는지 보는 검사는 그래프 전체를 봅니다. `--only <페이지>`를 주면 `save --only`로 저장한
페이지만 보므로, 다른 사람이 다른 곳을 쓰는 중에도 통과합니다.

스킬로 한 일에서 사용자가 지적한 실수는 그 뒤로 검사가 잡습니다. 에이전트는 일을 고치면서 그 스킬의
검사가 그 실수를 실패로 판정하게 하고, 실수를 재현한 경우(`expect: "fail"`)를 더합니다. 학습 스킬이면
이어서 `skills mistake <이름> --case "<경우>" --why "<요약>"`을 실행합니다. 이 명령은 그 경우가 fail을
기대하고 검사가 지금 그 경우를 실패로 판정할 때만 `skills.json`에 기록하며, 요청 문구를 옮긴 요약은
받지 않습니다.

lint는 기록된 경우를 계속 지킵니다. 그 경우를 지우거나 통과하는 경우로 바꾸면 lint가
실패하고, `upkeep`은 경우를 되살릴 때까지 그 스킬을 쓰지 않도록 합니다. `skills status`는 스킬마다
검사가 지키는 실수의 수를 보여 주고, 회고는 그런 교정을 찾았는데 아직 기록되지 않았으면 사용자에게
묻습니다. 엔진 스킬의 실수는 엔진에 고칠 점으로 알리며, 엔진에서 그 스킬 검사의 실패하는 경우가
됩니다. 모든 작업 폴더의 `AGENTS.md`에 이 규칙이 있습니다.

엔진의 스킬은 모두 100점이며 테스트가 이를 지킵니다. `conversations`를 켠 작업 폴더는 요청에서
스킬도 배웁니다. `skills candidates`는 비슷한 말(세 글자 조각으로 비교하므로 영어뿐 아니라
한국어도 됩니다)로 `windowDays` 안에 `minSessions`개 세션에서 `minRequests`번 이상 되풀이된 요청을
묶습니다.

`excudo-skills` 스킬이 후보를 하나씩 읽고, 대화나 한 번뿐인 일은 제외하며
(`skills dismiss <id> --reason …`), 되풀이되는 작업을 스킬로 만듭니다. 뼈대 스크립트가
`skills/<이름>/`을 만들고 에이전트가 절차와 검사를 채우면, `skills lint`가 점수를 매기고
`skills adopt <이름> --from <후보>`가 규칙과 `minScore`(기본 80)를 충족한 스킬을 설치합니다.
충족하지 못한 스킬은 초안으로 남습니다.

`skills upkeep`은 학습한 스킬을 검사하고 설치본을 갱신하며, 요청을 세고 휴면 스킬을 알립니다.
알려진 경우에서 시간이 초과되거나 네트워크, 인증 오류만 나면 판정할 수 있는 실행이 올 때까지 보류합니다.
일반 판정이 틀리거나 점수가 `minScore`보다 낮으면 그 스킬을 쓰지 않도록 합니다.
누가 고친 설치본은 그대로 두고 알립니다.
`skills retire <이름>`은 사용을 멈추며, `skills adopt <이름> --force`는 고친 설치본도 바꿉니다.

예약 실행이 의존하는 스킬은 `skills: { keep: ["release-notes"] }`에 적습니다.
관리 명령은 목록의 스킬을 내리거나 퇴역시키지 않습니다.
검사가 실패하면 설치를 유지하고, 실패한 검사와 `state: "held"`를 알린 뒤 종료 코드 1을 냅니다.
글과 JSON 출력 모두 같은 종료 코드를 냅니다. 검사를 고친 뒤 다시 관리합니다.

기록을 바꾸는 명령은 서로 기다립니다. `skills.json`은 스킬과 제외한 후보를 요청 키, 건수, 날짜로만
기록하고 요청 원문은 담지 않으며, `save`가 스킬 원본과 함께 커밋합니다. 스킬이나 `reflect.json`이
에이전트에게 입력한 문구를 git에 넣게 되면 `save`는 커밋하지 않습니다.

스킬은 그 작업을 하는 곳에 둡니다. 작업 폴더 자체의 일을 하는 스킬은 작업 폴더에 설치합니다. `.agents/skills/<이름>`과
`.claude/skills/<이름>`이 원본을 가리키며, `save`가 이 연결도 커밋합니다.

다른 폴더에서 하는 일을
맡는 스킬은 그 폴더가 저장소 하나뿐이더라도 `--global --why <이유>`로 어느 폴더에서나 쓰게 합니다.
사용자가 요청했다면 `--requested`를 씁니다. 설정이 `install: "global"`이 아닌데 둘 다 없으면 `adopt`는
스킬을 작업 폴더에 둡니다. 작업 폴더만의 일은 설정이 `install: "global"`이어도 `--workspace`로 작업 폴더에
둡니다. 전역에 두는 스킬은 `~/.agents/skills/<이름>`에 복사해서 원본을 밝힌
`SOURCE.md`를 두고 `~/.claude/skills`와 `~/.codex/skills`에서 연결합니다.

연결 Git 워크트리에서도 전역 설치본을 그 워크트리의 스킬 원본과 비교할 수 있습니다.
자체 설치 기록이 없으면 소유 체크아웃의 기록을 읽습니다.
설치본의 설치, 갱신, 삭제는 소유 체크아웃에서 실행합니다. 연결 워크트리는 설치본을 바꾸지 않습니다.

어느 작업 폴더에서나 하는
메모 작업은 엔진의 스킬에 맡기고, 에이전트의 기본 명령이 이미 하는 일은 스킬로 만들지 않습니다.
`upkeep`은 스킬마다 요청을 입력한 폴더를 알려 줍니다. 이 스킬의 검사는 작업 폴더에 두었지만 요청이
대부분 다른 폴더에서 나온 스킬을 찾아냅니다. 그런 스킬은 정작 그 폴더에서 읽히지 않기 때문입니다.
반대로 전역에 두었지만 요청이 모두 이 작업 폴더에서 나왔고 다른 폴더에 둘 이유도 없는 스킬도 찾아냅니다.

스킬은 채택한 자리에 그대로 남고, `--workspace`로 작업 폴더에 되돌릴 수 있습니다. 이 스킬을 예약 실행하면 사람 없이도 이어집니다. 예약 실행에서는 확실히 맞는 스킬만
만들어 채택하고 나머지는 사용자에게 남깁니다.
